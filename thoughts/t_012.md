## Muhakeme
StateManager şu an in-memory çalışıyor. Session kapanınca state kaybolur.
Persist lazım — state.json dosyasına yazma/okuma.

Tasarım kararları:

1. Ne zaman yazılmalı?
   → Her transition() sonrası otomatik. Crash-safe olmalı.
   → Ama her geçişte dosya I/O performans sorunu olabilir mi?
   → Hayır — state machine geçişleri saniyede max 1-2.
   → Her geçişte yaz, güvenli ol.

2. Dosya yolu nereden gelir?
   → ForemanState.projectRoot + "/state.json"
   → StateManager bunu biliyor çünkü state içinde projectRoot var.

3. Dosya yoksa ne olur?
   → StateManager.create() ile fresh state oluştur,
   → ilk transition'da dosya yaratılır.

4. Dosya bozuksa ne olur?
   → JSON.parse hatası → anlamlı hata mesajı, crash etme.
   → "State file corrupted, starting fresh" opsiyonu sunulabilir.
   → Ama otomatik silme tehlikeli. Hata fırlat, insan karar versin.

5. Atomik yazma?
   → write-to-temp + rename pattern — yarım yazma riski yok.
   → Node.js'te fs.writeFileSync + rename yerine basit writeFileSync
   yeterli şimdilik. Gerçek atomik yazma sonraki iterasyonda.

Persist fonksiyonlarını StateManager'a method olarak ekleyeceğim:
- save(): state.json'a yaz
- static load(projectRoot): state.json'dan oku ve StateManager döndür

transition() içinde otomatik save() çağrısı.
